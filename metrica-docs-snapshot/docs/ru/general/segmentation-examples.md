# Примеры сегментации

Выделим посетителей, которые просмотрели определенные страницы сайта (например, каталог товаров одной из категорий), чтобы с помощью Яндекс Директа предложить им товар или услугу, связанную с этими страницами.

1. В группе условий **для людей, у которых** нажмете кнопку .
2. Выберите условие: **Поведение** → **Просмотр URL**, в строке введите URL необходимой страницы (например, `https://example.com/tariff/`). Используйте `@example.com`, чтобы сегментировать отчет по всем страницам, в адрес которых входит `example.com`.
3. [Сохраните полученный сегмент](ru/general/segmentation-report#save).
4. В Директе [добавьте условие ретаргетинга и подбора аудитории](https://yandex.ru/support/direct/impression-criteria/retargeting-lists.html#retargeting-lists).

Из данных отчета [Источники, сводка](ru/sources/sources-summary) выделим посетителей, которые совершили заказ на сумму больше 10 000 руб.

1. В группе условий **Визиты, в которых** нажмите кнопку .
2. Задайте условие: **Электронная коммерция** → **Сумма покупки**, затем выберите значение **Больше** и укажите сумму заказа — 10 000.

Иногда большое количество внутренних переходов на сайте может говорить о том, что на каких-то страницах сайта отсутствует счетчик Метрики. Рассмотрим пример.

Посетитель пришел из внешнего источника на страницу сайта, на которой не было счетчика (допустим, `contacts.html`) и с нее сразу (в рамках того же визита) перешел на страницу сайта со счетчиком (`page1.html`). Выполнены два условия: визит начался с `page1.html` (так как о просмотре страницы `contacts.html` в Метрике нет данных из-за отсутствия на этой странице счетчика), но страница, с которой был переход (`contacts.html`) принадлежит тому же сайту, что указан в настройках счетчика — `http://mysite.example/`.

Чтобы определить страницу, на которой не установлен счетчик, выполним следующее:

1. В отчете [Содержание - Страницы входа](ru/content/entry-pages) в группе условий **Визиты, в которых** нажмите кнопку .
2. Выберите условие: **Источники** → **Последний источник** → **Тип источника** → **Внутренние переходы**.
3. В списке группировок оставьте только группировку **Страница входа**. Для этого нажмите кнопку **Группировка** и удалите лишнее.

Таким образом, мы получили информацию о страницах, с которых начался визит. Чтобы определить откуда произошел переход на эти страницы, добавим группировку по рефереру (источнику) начала визита:

1. Нажмите кнопку **Группировки**.
2. Выберите группировку **Источники** → **Реферер**.

Теперь в отчете отображаются страницы, с которых начался визит, а на втором уровне дерева отчета — страницы, с которых был произведен переход. Для удобства можно перенести группировку **Реферер** на первое место в списке группировок. Тогда на первом уровне мы увидим те страницы, на которых предположительно может не быть кода счетчика, а на втором — куда вели переходы с них.

Малое количество визитов в таком отчете означает, что, вероятнее всего, со счетчиком все в порядке, а причиной внутренних переходов является [истечение тайм-аута визита](ru/sources/sources-summary).

Сотовый оператор добавил на сайт калькулятор тарифных планов.

Чтобы оценить эффективность нового инструмента, необходимо сравнить статистику по посетителям, которые воспользовались калькулятором и тем, которые им не воспользовались (например, в первые 14 дней после запуска инструмента). Также будет полезно оценить источники посещений. Сделать это поможет сегментация. Предположим, что для счетчика уже [создана цель](ru/general/goals) — взаимодействие с калькулятором тарифов («Калькулятор»).

В отчете [Источники, сводка](ru/sources/sources-summary) выделим из общего количества посещений визиты новых посетителей, которые достигли цель «Калькулятор»:

1. В группе условий **Визиты, в которых** нажмем кнопку .
2. Выберем условие **История** → **Новый/Вернувшийся посетитель** → **Новый посетитель**.
3. Нажмем кнопку .
4. Выделим визиты, в которых была достигнута цель «Калькулятор»: **Поведение** → **Достижение цели**, из предложенного списка выберем необходимую цель.

Затем уточним данные, оставив информацию о посетителях, которые просмотрели страницы тарифных планов с калькулятором в период с 1 по 15 марта. Страницы тарифов являются типовыми для сайта, на всех страницах размещен калькулятор. Поэтому в условии можно указать URL всего каталога «tariff» с помощью символа *.

1. В группе условий **для людей, у которых** нажмем кнопку .
2. Выберем условие: **Поведение** → **Просмотр URL**. В поле для ввода введем адрес каталога тарифных планов.
3. Выберем период времени просмотра страницы: нажмем кнопку **За отчетный период**, затем — **Выбрать период**.

В результате мы получили статистическую информацию о посетителях, которые воспользовались калькулятором тарифов в заданный период времени в прошлом. Сохраним сегмент.

Затем получим средние данные о пользователях сайта — удалим условие **Достижение цели** и сохраним сегмент под другим именем. Теперь мы можем сравнить два сегмента.

Вы можете исключить данные с упоминанием бренда из отчета. Для этого воспользуйтесь сегментацией и добавьте условие вида `!@ваш_бренд` для русского и английского вариантов бренда, где:

- ! в начале — отрицание условия;
- @ в начале — вхождение строки (регистр не учитывается).

Например, для компании «Алиса в стране чудес» регулярное выражение может выглядеть `!@алиса в стране чудес` для русского варианта бренда и `!@alice in wonderland` — для английского. Этим способом можно убрать из отчета не более 20 фраз. Чтобы исключить более 20 фраз, используйте регулярное выражение `!~(бренд|бренд.рф|brend.ru)`.
